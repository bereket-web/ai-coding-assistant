# CodePilot — AI Coding Assistant

CodePilot is a small, local-first coding assistant for explaining code, reviewing likely bugs, suggesting improvements, drafting tests, and summarizing files. It includes a responsive browser interface and JSON API. The default path works without an API key: Python source is parsed into an AST and checked by a small set of transparent heuristics. An optional OpenAI-compatible model can provide broader language-aware feedback when the user explicitly selects model mode.

**Suggestions are not guaranteed correct, complete, secure, or suitable for production.** CodePilot never executes submitted source. It is a review aid, not a compiler, test runner, static-analysis suite, or security audit.

## Run locally

Requires Python 3.10+; `uv` is recommended.

```bash
uv sync --extra test
uv run codepilot
```

Open <http://127.0.0.1:8000>. The service binds to loopback by default; interactive API documentation is at <http://127.0.0.1:8000/docs> and health status is at `/health`.

Paste code and choose one of five tasks: explain, find likely bugs, suggest improvements, draft tests, or summarize. The built-in offline analyzer currently inspects Python syntax and a few heuristic patterns. Other languages are passed to the optional model only when the user checks the model-mode box; offline responses are limited to general guidance.

## Optional model mode

Model mode is off by default and requires explicit selection for each request. It sends the pasted code and context to the endpoint configured by the application owner. Configure a compatible chat-completions provider in the process environment (do not commit secrets):

```bash
export CODEPILOT_API_BASE="https://api.openai.com/v1"
export CODEPILOT_API_KEY="replace-with-your-key"
export CODEPILOT_MODEL="gpt-4o-mini"
uv run codepilot
```

`OPENAI_API_KEY` and `OPENAI_API_BASE` are accepted as fallback environment variables. See `.env.example` for names only. Provider terms, retention, and data handling are outside this prototype's control. Do not send credentials, private records, or proprietary source unless you have permission and accept the configured provider's policies. No request content is intentionally logged by this application; reverse proxies, hosting platforms, and the provider may have their own logs or retention.

## API

`POST /api/analyze` accepts JSON:

```json
{
  "task": "bugs",
  "language": "Python",
  "code": "def f(x=[]):\\n    return x",
  "context": "Optional project-specific behavior",
  "use_model": false
}
```

The response includes a result, mode, warning, Python structural facts, heuristic findings, and `code_was_executed: false`. Input limits are 24,000 code characters and 3,000 context characters. The app returns local heuristic output if an explicitly requested provider is missing or unavailable.

## What is actually analyzed

Python parsing uses the standard-library `ast` module; it does not import or run the submitted code. Current deterministic checks flag syntax errors, mutable defaults, bare/broad exception handlers, `eval`/`exec`, and equality checks against `None`. These rules are a deliberately small starter set and can produce false positives or miss issues. Structural summaries list functions, classes, imports, and approximate file size. The offline test task emits skipped pytest scaffolds rather than inventing test data or claiming tests pass.

Model results are generated by the configured external service. Prompt instructions treat code as untrusted data, but this is not a security boundary and no provider output is independently verified. Humans must inspect proposed edits, run formatters, tests, type checks, and security tools appropriate to their project.

## Checks and evaluation

```bash
uv run pytest
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
uv run python scripts/evaluate.py
uv build
```

Tests verify expected triggers for hand-written snippets, request limits, response shape, and that the API reports no code execution. The synthetic evaluation is a regression fixture for the implemented rules, not a labeled real-world corpus: it does not estimate precision, recall, bug-finding quality, model quality, or usefulness on arbitrary projects. No trained model, external code dataset, or benchmark result is claimed.

## Security and limitations

- Never executes, imports, compiles, or installs submitted code.
- Binds to `127.0.0.1` by default, with no authentication, authorization, rate limiting, or deployment hardening. Do not expose it publicly without adding those controls and reviewing the complete stack.
- Supports Python-only AST checks. No TypeScript/Java/C++ parser, code indexing, repository-aware context, agent tools, patch application, or execution sandbox is included.
- Model mode transmits the snippet and supplied context to the configured endpoint. Do not treat prompt text as a guarantee against prompt injection or data exposure.
- Generated tests may be incomplete or have incorrect assumptions. Offline scaffolds are intentionally skipped until filled with correct fixtures and assertions.
- A clean heuristic scan does not mean the code is correct, bug-free, performant, or secure.
